## 2. Мета роботи

Підготувати консольну програму для обробки даних метеостанції та відтворювану
збірку, яку можна перевірити на Linux, Windows і macOS.

Досягнуто:

- читання CSV, перевірка п'яти полів і пропуск некоректних записів із поясненнями;
- обчислення чотирьох показників за коректними записами;
- формування одного звіту для консолі та файла UTF-8;
- збірка через Maven Wrapper, JUnit 5, SpotBugs і виконуваний JAR;
- GitHub Actions із перевірками на трьох ОС, кешем Maven і JAR-артефактами;
- ведення роботи через GitHub Issues, гілки та Pull Request.

## 3. Постановка задачі

Формат одного запису:

~~~text
date:String;temperature:double;humidity:double;pressure:double;wind:double
~~~

CSV має кодування UTF-8, не містить заголовка. Поля розділено крапкою з комою,
крайні пробіли прибираються. Десятковий роздільник — крапка.

Показники варіанта 18:

1. Кількість коректних записів.
2. Мінімальна температура, °C.
3. Середня вологість, %.
4. Максимальна швидкість вітру, м/с.

| Поле | Правило перевірки |
|---|---|
| date | Непорожній текст формату YYYY-MM-DD; календарна правильність дати не перевіряється |
| temperature | Скінченне число; від'ємне значення допустиме |
| humidity | Скінченне число від 0 до 100 включно |
| pressure | Додатне скінченне число, одиниця — гПа |
| wind | Скінченне невід'ємне число, одиниця — м/с |

У рядку має бути рівно п'ять полів. Розділення з параметром -1 зберігає
порожнє останнє поле. Хибні числа, порожні числові поля, NaN та
нескінченність відхиляються. Перша знайдена проблема стає причиною пропуску;
повідомлення містить фізичний номер рядка. Програма продовжує читати наступні
записи. Некоректний рядок не змінює статистику.

Тиск перевіряється, хоча не входить до обчислюваних показників. Якщо немає
коректних записів, звіт містить «Немає даних» і кількість 0; ділення на нуль
не виконується.

Методи Main:

| Метод | Відповідальність |
|---|---|
| main | Розбирає --input/--output, обробляє --help/--version та викликає обробку один раз |
| readInput | Читає рядки через Files.readAllLines із явним UTF-8 |
| processInput | Перевіряє рядки, накопичує статистику й помилки, формує reportText |
| writeReport | За потреби створює папки й записує reportText у UTF-8; пояснює помилки запису |
| printHelp | Виводить довідку |
| printVersion | Читає Maven-ресурс і показує версію та номер збірки |

Потік даних:

~~~text
args → main → readInput → рядки → поля та перевірки
     → коректні записи: статистика / хибні записи: список errors
     → reportText → консоль + writeReport → файл UTF-8
~~~

Основна реалізація збережена в одному класі, а читання, запис і обробка
виділені в методи. Для наступної лабораторної рядкові поля можна буде
замінити власним класом метеовимірювання.

### Версія коду та номер CI-збірки

Версія 1.0.0 описує версію програми й зазначена в pom.xml та --version.
Номер CI-збірки — порядковий номер запуску GitHub Actions. Він передається
через build.number та входить у назву артефакта. Повторна збірка того самого
коду може мати інший номер; локальна збірка використовує значення local.

Перевірений локальний вивід:

~~~text
lab01 1.0.0 (build local)
~~~

Завантажений Linux JAR із CI тега №45 вивів:

~~~text
lab01 1.0.0 (build 45)
~~~

Версія 1.0.0 узгоджена в обох pom.xml, Git-тегу v1.0.0 та виводі --version.
Номер 45 означає запуск CI, а не іншу версію програми.

## 7. Приклади роботи

Вхідний файл LAB_01/data/input.csv:

~~~text
2026-09-01;-5.5;70.0;1013.0;3.2
2026-09-02;2.0;80.0;1008.0;7.5
2026-09-03;10.0;60.0;1010.0;1.8
2026-09-04;4.0;помилка;1012.0;2.0
2026-09-05;6.0;65.0;1011.0;-1.0
~~~

Запуск із кореня репозиторію:

~~~sh
./mvnw -B clean verify
java -jar LAB_01/target/lab01.jar --input LAB_01/data/input.csv --output out/report.txt
~~~

У консолі спочатку виводяться коректні записи:

~~~text
Рядок 1: дата 2026-09-01, температура -5.5 °C, вологість 70.0 %, тиск 1013.0 гПа, вітер 3.2 м/с
Рядок 2: дата 2026-09-02, температура 2.0 °C, вологість 80.0 %, тиск 1008.0 гПа, вітер 7.5 м/с
Рядок 3: дата 2026-09-03, температура 10.0 °C, вологість 60.0 %, тиск 1010.0 гПа, вітер 1.8 м/с
~~~

Далі друкується підсумок із помилками. Саме цей текст записується в out/report.txt:

~~~text
Мінімальна температура: -5.50 °C
Максимальна швидкість вітру: 7.50 м/с
Середній рівень вологості: 70.00 %
Кількість коректних записів: 3
Помилки:
Рядок 4: вологість не є числом; вхід: 2026-09-04;4.0;помилка;1012.0;2.0
Рядок 5: вітер має бути скінченним невід’ємним числом; вхід: 2026-09-05;6.0;65.0;1011.0;-1.0
~~~

Ручна перевірка: коректних записів 3; min(-5.5, 2, 10) = -5.5;
(70 + 80 + 60) / 3 = 70; max(3.2, 7.5, 1.8) = 7.5.

Приклади повідомлень про помилки запуску:

~~~text
$ java -jar LAB_01/target/lab01.jar --input
Після --input бракує шляху

$ java -jar LAB_01/target/lab01.jar --input missing.csv
Не вдалося прочитати файл missing.csv: missing.csv
~~~

Для порожнього файла:

~~~text
Немає даних
Кількість коректних записів: 0
~~~

## 8. Тестування

Локальна перевірка на EndeavourOS / OpenJDK 21:

~~~text
./mvnw -B clean verify
Tests run: 12, Failures: 0, Errors: 0, Skipped: 0
BugInstance size is 0
Error size is 0
BUILD SUCCESS
~~~

У MainTest кожен тест має явні вхідні дані й очікуваний результат.
JUnit створює тимчасові папки; допоміжні методи запускають Main і читають
звіт. Після перехоплення виводу stdout/stderr відновлюються.

| Тест | Що перевіряє |
|---|---|
| calculatesFourStatistics | Чотири показники, від'ємна температура та дробове середнє з похибкою |
| acceptsSpacesAndBoundaryValues | Пробіли, вологість 0/100, додатний тиск і нульовий вітер |
| rejectsWrongStructureAndEmptyFields | Порожній рядок/поля, кількість полів, дата, фізичні номери рядків |
| rejectsWrongNumbersAndNonFiniteValues | Хибні числа, NaN та нескінченності в числових полях |
| invalidRecordsDoNotChangeStatistics | Межі вологості, вітер/тиск; наступні коректні записи обробляються |
| emptyFileHasNoData | Порожній файл, кількість 0, відсутність вигаданих показників |
| helpAndVersionDoNotReadInput | --help та --version без обробки CSV |
| invalidArgumentsAreExplained | Невідомий параметр, відсутнє значення, інший параметр замість шляху |
| ukrainianPathsAndReversedOptionsWork | UTF-8, українські шляхи й обидва порядки --input/--output |
| missingInputIsExplained | Відсутній вхідний файл |
| writeFailureIsExplained | Помилка запису відрізняється від помилки читання |
| germanLocaleStillUsesDecimalPoint | Незалежність десяткового роздільника від локалі |

Додатково CI запускає зібраний JAR із тимчасової робочої папки, задає
--output report.txt без батьківського каталогу та звіряє файловий звіт
із підсумком у консолі. Також CI запускає JAR із --help і перевіряє
текст довідки; окремий крок перевіряє --version і номер збірки.

## 9. Документація

[README.md](README.md) містить призначення програми, встановлення Git/JDK,
клонування, збірку та запуск для Linux, macOS і Windows, формат CSV,

етапи та критерії роботи; [ai/USAGE.md](ai/USAGE.md) — журнал допомоги ШІ.

Javadoc-коментарі додано до Main, його публічного конструктора, main,
processInput, writeReport, printVersion, printHelp і readInput. Вони описують
призначення, параметри, результат читання та можливі винятки. Конструктор
лише явно відтворює порожній публічний конструктор, який раніше створювала Java.

Генерація HTML-документації з кореня репозиторію:

~~~sh
javadoc -private -encoding UTF-8 -charset UTF-8 -docencoding UTF-8 -d LAB_01/target/apidocs LAB_01/src/main/java/Main.java
~~~

Генерація перевірена локально без помилок і попереджень. Початкова сторінка —
LAB_01/target/apidocs/index.html. Згенеровані файли не входять до Git;
після clean їх потрібно створити повторно. Параметр -private включає
документацію допоміжних методів.
