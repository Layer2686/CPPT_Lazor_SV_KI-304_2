# Звіт до лабораторної роботи №5

## 1. Тема, номер і варіант

- Тема: параметризоване сховище, винятки й CSV-експорт у Java-проєкті.
- Лабораторна робота №5, варіант 18 — «Метеостанція».
- Виконав: Лазор С. В., група КІ-304, підгрупа 2.
- ОС перевірки: Linux; JDK 21, UTF-8. CI: Ubuntu, Windows і macOS.
- Репозиторій: [CPPT_Lazor_SV_KI-304_2](https://github.com/Layer2686/CPPT_Lazor_SV_KI-304_2).
- Модуль LAB_05, пакет ua.lpnu.kzp.lab05; версія **1.4.0**.

## 2. Мета роботи

Додати до метеостанції типобезпечне сховище, власний виняток із причиною,
анотації та універсальний експорт через рефлексію. Зберігати й відновлювати
об’єкти через UTF-8 CSV без втрати значень, порядку та повторених дат.
Зберегти попередні поліморфні об’єкти, запити й формат стандартного звіту.

## 3. Стан до та після роботи

| Попередній стан | Результат п’ятої роботи |
| --- | --- |
| Вимірювання й Stream-запити в пам’яті | Repository<T>, незалежний знімок і пошук Predicate |
| CSV із ; тільки для початкового вводу | Додатковий CSV з комами, заголовком, escaping та імпортом |
| Обробка технічних винятків окремими компонентами | DataStorageException з контекстом та cause |
| Немає універсального запису об’єктів | @CsvColumn і рефлексивні CSV/JSON експортери |
| Немає перевірки збереження-відновлення | Порівняння повних списків original.equals(restored) |
| Попередні --danger та --queries | Ті самі аналізи для початкових та імпортованих даних |

Main передає аргументи парсеру й запускає контролер. Файлові операції,
перетворення моделей, формування звіту й нові формати належать окремим класам.

## 4. Repository<T>

Параметр T визначає тип записів: Repository<WeatherReading> приймає
вимірювання, Repository<String> — рядки. Raw types не застосовуються.
Приватний ArrayList недоступний зовні. Add відхиляє null; all повертає
List.copyOf — незмінний незалежний знімок структури списку. Пізніше додані
записи не з’являються в попередньому знімку; самі об’єкти не клонуються.

Find приймає Predicate<? super T>: умову для T або його супертипу.
Filter залишає збіги, toList повертає незмінний список. Порядок і дублікати
збережені; null-предикат відхиляється. Контролер накопичує в сховищі лише
коректні записи старого вводу та передає знімок до запитів і звітів.

## 5. Модель даних

WeatherReadingRecord — окремий незмінний final-клас для зберігання.
Усі поля private final, сеттерів немає; гетери повертають значення.

| Поле | Java-тип | Інваріант / одиниці |
| --- | --- | --- |
| date | LocalDate | не null; календарна дата |
| temperature | double | скінченне число, °C; від’ємні дозволено |
| humidity | double | скінченне число 0–100 % |
| pressure | double | скінченне число >0 гПа |
| wind | double | скінченне число >=0 м/с |

Конструктор перевіряє дані; порушення інваріантів дає IllegalArgumentException.
Equals порівнює клас, дату та всі чотири double через Double.compare.
HashCode враховує ті самі дані. Однаковий хеш не замінює equals.

FromReading створює плоский запис із поліморфного вимірювання; toReading
використовує попередній Builder. DailyReading відповідає wind<15, StormReading
— wind>=15; dangerIndex лишається wind або wind*2. WeatherReading залишається
abstract sealed; WeatherKind і TemperatureHumidity record збережені.
WeatherReadingRecord — назва звичайного класу, а не Java record.

## 6. @CsvColumn та порядок колонок

Анотація містить лише String value(). RetentionPolicy.RUNTIME забезпечує
читання під час виконання; ElementType.FIELD дозволяє застосування до полів.
Позначені всі п’ять полів моделі. Value задає український заголовок.

Поля сортуються за Java-іменем: date, humidity, pressure, temperature, wind.
Заголовок і дані отримані з одного списку полів. Порядок відрізняється від
старого вводу date;temperature;humidity;pressure;wind і визначений явно.
Імпортер перевіряє точний заголовок у погодженому порядку.

## 7. Універсальний рефлексивний експортер

CsvExporter<T>.write(Path, Class<T>, List<? extends T>) не містить назв
погодних полів або умов за підтипом. Class<T> потрібний для заголовка
навіть за порожнього списку. Список дозволяє T та його підтипи.

ColumnMetadata отримує getDeclaredFields, залишає @CsvColumn, пропускає
static/неанотовані поля, сортує Field.getName та перевіряє trySetAccessible.
Порожній список метаданих, порожні/повторені назви й заборонений доступ
дають DataStorageException. Успадковані та вкладені поля не обходяться.

Field.get(record) читає значення конкретного об’єкта. Значення екрануються
та з’єднуються комами; null-поле CSV означає порожню клітинку. Null-запис,
клас або список відхиляються. Текст формується перед файловим записом.
Files.writeString використовує UTF-8, CREATE/TRUNCATE_EXISTING/WRITE.
Батьківські папки створюються лише за наявності parent; файл без папки
також підтримується. Попередній вміст файла не дописується.

## 8. Фактичний CSV та екранування

Результат запуску JAR на data/queries-example.csv:

```csv
дата,вологість,тиск,температура,вітер
2026-09-01,70.0,1013.0,10.0,7.5
2026-09-02,60.0,1010.0,25.0,15.0
2026-09-03,65.0,1009.0,25.0,20.0
2026-10-01,80.0,1005.0,-5.0,14.99
2026-10-02,55.0,1012.0,18.0,15.01
2026-10-03,75.0,1011.0,5.0,0.0
2026-09-02,50.0,1008.0,12.0,16.0
```

Новий CSV має UTF-8 без BOM і LF незалежно від ОС. Парсер підтримує також
CRLF та CR. Усередині quoted-значень переноси зберігаються точно.

П’ять погодних полів не містять довільного тексту. Для доведення
універсальності той самий експортер застосований до іншого плоского класу
з полями code/description та назвами код/опис. Фактично створений файл:

```csv
код,опис
A-1,"Текст, із комою та ""лапками"""
A-2,"Перший рядок
Другий рядок"
```

Кома, лапка, CR або LF потребують зовнішніх лапок. Внутрішня лапка
подвоюється. Тут 4 фізичних рядки, але лише 3 логічних записи з заголовком
і 2 відновлювані об’єкти. У погодному файлі — 8 фізичних рядків,
8 логічних записів із заголовком, 7 об’єктів. Нові поля до варіанта не додані.

## 9. Імпорт і доказ round-trip

WeatherCsvStorage читає весь файл через Files.readString з UTF-8.
CsvParser.parseDocument використовує стани START, UNQUOTED, QUOTED,
AFTER_QUOTE. Коми та переноси завершують клітинки/записи лише поза лапками;
подвоєні лапки відновлюються. Порожня остання клітинка не втрачається.
Незакриті лапки й сторонні символи після закривальної лапки відхиляються.

WeatherReadingRecord.fromFields перевіряє п’ять клітинок, розбирає дату й
числа та викликає конструктор із валідацією. FromCsv приймає один логічний
запис без заголовка. Порожній файл і лише правильний заголовок дозволені:
результат — порожній список. Неправильний заголовок не ігнорується.
При хибному рядку весь імпорт завершується помилкою без часткового результату.

Ключ демонстрації — date. Порівнюється весь список original.equals(restored),
а не карта за унікальною датою: повторні вимірювання не зникають.

| Позиція | Original: дата / температура / вітер | Restored | equals |
| --- | --- | --- | --- |
| 2 | 2026-09-02 / 25.0 / 15.0 | ті самі значення всіх п’яти полів | true |
| 7 | 2026-09-02 / 12.0 / 16.0 | ті самі значення всіх п’яти полів | true |
| Повний список | 7 записів у початковому порядку | 7 записів із дубльованою датою | true |

Консоль: `Round-trip: true (записів: 7)`. Окремий тест порівнює також
відновлені DailyReading/StormReading з початковими поліморфними об’єктами.

## 10. Помилки та першопричина

DataStorageException extends Exception має конструктори message та
message/cause. Технічна помилка не приховується порожнім catch.
Для самостійно виявленої структурної помилки cause не вигадується.

| Помилка | Контекст повідомлення | Cause | Перевірка |
| --- | --- | --- | --- |
| Некоректний інваріант моделі | Некоректне вимірювання та початкова причина | IllegalArgumentException | WeatherCsvStorageTest |
| Число «помилка» у вологості | Запис 2: Некоректне число у полі вологість | NumberFormatException | WeatherCsvStorageTest |
| Неможлива дата 2026-02-31 | Некоректне поле дата | DateTimeParseException | WeatherCsvStorageTest |
| Невідома категорія допоміжного типу | Невідома категорія: UNKNOWN | IllegalArgumentException | StorageRegressionTest |
| Неправильний заголовок/кількість клітинок | Очікуваний заголовок або 5 полів | Необов’язкова | WeatherCsvStorageTest |
| Неправильні лапки | Номер логічного запису та синтаксична причина | Необов’язкова | CsvParserTest |
| Відсутній файл / запис у каталог | Читання/запис CSV та шлях | IOException | CsvExporterTest, WeatherCsvStorageTest |
| Заборонений рефлексивний доступ | Клас/поле, яке не вдалося прочитати | Виняток доступу, якщо кинутий | Обробка в ColumnMetadata/CsvExporter |
| Шляхи джерела/результатів збігаються | Шляхи мають відрізнятися | Необов’язкова | StorageCliTest |

Структурні й технічні помилки нового імпорту припиняють операцію.
Старий --input зберігає попередню політику: помилка рядка повідомляється,
наступні рядки обробляються, у статистику й експорт потрапляють лише коректні.

## 15. Другий формат і кеш — завдання із зірочкою

CsvExporter та JsonExporter реалізують Exporter<T> й використовують
ті самі метадані ColumnMetadata. JSON зберігає числові й boolean-типи,
null; дату, enum і текст подає рядками. Лапки, зворотний слеш та керівні
символи екрануються; NaN/Infinity і вкладені об’єкти відхиляються.
CSV лишається обов’язковим форматом для імпорту й round-trip.

Кеш ConcurrentHashMap<Class<?>, List<Field>> містить лише описи полів,
а не значення записів. Порядок і перевірка доступу однакові для CSV/JSON.
CsvExporter(false) вимикає кеш для експерименту. Кеш живе протягом процесу;
динамічне розвантаження classloader не є сценарієм цього застосунку.

ExportBenchmark: 10 000 записів, 100 файлів по 100; 3 прогріви, 7 повторів,
чергування режимів, медіана. Виміряно повний CSV-експорт із файловим I/O.
Linux amd64, Java 21.0.12.1. Без кешу — **12.902 мс**, із кешем — **11.438 мс**.
Усі 100 пар CSV побайтово однакові. Це локальний результат, а не гарантія
прискорення на кожному комп’ютері. JIT/GC/кеш ОС впливають на час;
автоматичні тести не порівнюють швидкість. Повні сирі виміри:
[BENCHMARK.md](BENCHMARK.md).

```sh
java -cp LAB_05/target/lab05.jar ua.lpnu.kzp.lab05.ExportBenchmark
```
