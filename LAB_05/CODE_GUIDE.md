# Пояснення коду лабораторної №5

Цей текст читається разом із файлами пакета `ua.lpnu.kzp.lab05`.
Найкоротший маршрут: Repository → WeatherReadingRecord/CsvColumn →
CsvExporter → CsvParser → WeatherCsvStorage → StorageWorkflow.

## 1. Повний шлях даних

```text
main(args)
  → ArgumentParser.parse(args)
  → CommandLineOptions (параметри)
  → WeatherController.run(options)
      старий CSV → WeatherReading.fromCsv → Repository<WeatherReading>
      новий CSV → WeatherCsvStorage → WeatherReadingRecord → toReading
  → WeatherReport / QueryReport (попередня робота)
  → StorageWorkflow
      fromReading → List<WeatherReadingRecord>
      CsvExporter / JsonExporter → файл
      WeatherCsvStorage.read → restored
      original.equals(restored)
```

**Клас** описує тип і його методи; **об’єкт** — конкретний створений екземпляр.
Наприклад, `new CsvExporter<WeatherReadingRecord>()` створює об’єкт експортера.
`new` викликає конструктор; змінна `exporter` зберігає посилання на цей об’єкт.

## 2. Repository<T>: сховище

`T` — параметр типу. У `Repository<WeatherReading>` метод add приймає
WeatherReading, а у `Repository<String>` — String. Це перевіряє компілятор.
Приватний `List<T> items = new ArrayList<>()` — змінний внутрішній список.

- Конструктор Repository() створює порожній об’єкт сховища.
- `add(T item)` перевіряє non-null і додає об’єкт у кінець.
- `all()` повертає `List.copyOf(items)`: незалежний незмінний список.
  Якщо пізніше додати об’єкт у сховище, попередній знімок не збільшиться.
  Самі об’єкти не клонуються; наша погодна модель незмінна.
- `find(Predicate<? super T> condition)` відбирає елементи через filter.
  Predicate — функція «елемент → true/false»; `? super T` дозволяє умову
  для T або його супертипу. Результат toList незмінний, дублікати збережені.

## 3. DataStorageException: зрозуміла помилка з причиною

`extends Exception` означає checked-виняток. Метод або оголошує
`throws DataStorageException`, або обробляє його через catch.

Конструктор з message викликає `super(message)`. Другий приймає також
Throwable cause і викликає `super(message, cause)`. Тому getMessage пояснює
операцію, а getCause зберігає IOException/NumberFormatException тощо.
`serialVersionUID` з @Serial — ідентифікатор серіалізованого типу винятку.

У catch не повертається порожній список замість пошкодженого файла:
це приховало б помилку. Контролер показує повідомлення через System.err.
Він не друкує весь stack trace; cause можна переглянути в debugger або тесті.

## 4. CsvColumn: метадані над полем

```java
@CsvColumn("температура")
private final double temperature;
```

`@interface` оголошує тип анотації. `String value()` — єдиний її елемент.
Текст `"температура"` передається саме як value.

- `@Retention(RetentionPolicy.RUNTIME)` залишає її доступною після компіляції.
- `@Target(ElementType.FIELD)` дозволяє ставити її над полями.
- Анотація нічого не записує самостійно: її читає експортер.

## 5. WeatherReadingRecord: один рядок збережених даних

Це звичайний final-клас, хоча в назві є Record. П’ять private final полів:
LocalDate date і double temperature/humidity/pressure/wind. Final-клас
не можна успадкувати; final-поля призначаються при створенні й не змінюються.

Конструктор приймає всі п’ять значень. `this.date = date` означає:
ліворуч поле створюваного об’єкта, праворуч параметр конструктора.
Перевіряються дата, скінченні числа, вологість 0–100, тиск >0, вітер >=0.
Якщо перевірка кидає виняток, виклик new не поверне готового об’єкта.
Гетери лише повертають поля; сеттерів немає.

- `equals(Object other)` перевіряє ту саму адресу, null/клас, далі всі значення.
  Приведення `(WeatherReadingRecord) other` не створює об’єкта: дає типізоване
  посилання на вже перевірений об’єкт. Double.compare порівнює double-поля.
- `hashCode()` обчислює хеш із тих самих значущих даних; рівні записи мають
  однаковий хеш. Однаковий хеш сам по собі не доводить рівність.
- `static fromReading(reading)` створює плоский запис через гетери попередньої
  моделі. Static викликається через ім’я класу, без власного екземпляра.
- `toReading()` збирає колишній об’єкт через Builder; Builder вибирає
  DailyReading або StormReading. Формули небезпеки з третьої роботи збережені.
- `csvHeader()` повертає точний контракт імпорту: дата,вологість,тиск,температура,вітер.
- `fromFields(fields)` перевіряє п’ять клітинок, читає LocalDate і double,
  передає значення конструктору. **Порядок CSV відрізняється від порядку
  параметрів конструктора**: humidity у CSV друга, temperature — четверта.
- `parseNumber(value, name)` додає назву поля до NumberFormatException.
- `fromCsv(csv)` розбирає один логічний запис без заголовка через CsvParser
  та передає клітинки fromFields. Це новий формат із комами; попередній
  WeatherReading.fromCsv читає інший формат із крапками з комою.

Навіщо окрема плоска модель: CSV зберігає саме п’ять колонок, а sealed-класи
продовжують відповідати за поліморфну поведінку й попередні запити.

## 6. ColumnMetadata: рефлексія та кеш

`Class<T>` описує клас, а не конкретний погодний об’єкт. Наприклад,
`WeatherReadingRecord.class` дає інформацію про поля цього типу.
`Field` описує одне поле: ім’я, тип, анотації та спосіб читання.

`inspect(recordType)` виконує:

1. getDeclaredFields — масив полів, оголошених саме в цьому класі.
2. Arrays.stream — потік описів полів.
3. filter з isAnnotationPresent — залишити поля з CsvColumn.
4. filter з Modifier.isStatic — виключити поля класу.
5. sorted з Field::getName — детермінований алфавітний порядок.
6. trySetAccessible — дозволити рефлексивне читання private-полів.
7. Перевірити непорожні унікальні назви колонок.

Успадковані поля не обходяться. Для забороненого доступу повертається
власний виняток, а не порожні значення.

`columns(type, cached)` вибирає inspect або кеш. Кеш — ConcurrentHashMap:
ключ Class, значення List<Field>. get перевіряє готові метадані,
putIfAbsent безпечно додає їх, якщо інший потік ще не додав.
Кешуються **описи полів, не погодні значення**. field.get(record)
кожного разу читає переданий запис. Кеш живе до завершення процесу.

## 7. Exporter<T> та CsvExporter<T>

Інтерфейс Exporter задає спільний метод write(path, type, records).
Класи CsvExporter і JsonExporter реалізують цей контракт через implements.
Змінна `Exporter<WeatherReadingRecord>` може посилатися на будь-який із них;
виклик write виконає метод конкретного об’єкта.

`List<? extends T>` дозволяє список T або його підтипів, який експортер читає.
Окремий Class<T> потрібний навіть для порожнього списку, щоб отримати колонки.

Конструктор CsvExporter() вмикає кеш. CsvExporter(false) вимикає його
для порівняння часу. Boolean-поле cacheEnabled зберігає цей вибір.

- `getColumns(type)` делегує отримання полів ColumnMetadata.
- `buildHeader(columns)` бере value анотації, екранує назви й з’єднує комами.
- `escapeCsv(value)` перевіряє кому/лапку/CR/LF. Якщо треба, подвоює
  внутрішні лапки й додає зовнішні. Інакше повертає початковий текст.
- `toCsv(type, records)` створює StringBuilder із заголовком. Для кожного
  запису перевіряє тип/non-null, потім для кожного Field читає `field.get(record)`.
  Objects.toString(value, "") перетворює значення на текст, null — на порожню
  клітинку. Після escaping значення з’єднуються комами, записи — LF.
- `write(...)` отримує готовий текст через toCsv і передає його StorageFiles.
  Валідація відбувається до запису; неправильний об’єкт не обнулить старий файл.

Універсальність: у класі експортера немає викликів getTemperature,
переліку погодних полів чи if за DailyReading/StormReading.

## 8. StorageFiles: UTF-8 і файлові помилки

write перевіряє Path, бере getParent, створює папку лише якщо parent не null,
записує Files.writeString із UTF_8 та CREATE/TRUNCATE_EXISTING/WRITE.
TRUNCATE_EXISTING видаляє попередній вміст, тому коротший новий файл не має
старого хвоста. Шлях `weather.csv` працює без батьківської папки.

read використовує Files.readString з UTF_8: повертає **весь документ**.
IOException та SecurityException перетворюються на DataStorageException
із контекстом операції, шляхом і початковою cause.

## 9. CsvParser: навіщо чотири стани

parseDocument проходить документ один раз, символ за символом.
Стан визначає значення наступної лапки, коми або переносу:

| Стан | Значення |
| --- | --- |
| START | Початок нового поля; лапка може відкрити quoted-поле |
| UNQUOTED | Звичайний текст; лапка тут є помилкою |
| QUOTED | Коми й переноси є даними; лапка переводить у AFTER_QUOTE |
| AFTER_QUOTE | Ще одна лапка означає одну лапку в даних; кома/перенос завершують поле |

У QUOTED символи накопичуються у StringBuilder value. Поза лапками кома
додає клітинку до row; CR/LF додають рядок до rows. CRLF з’їдається як
одна межа запису. Усередині лапок CRLF зберігається двома символами.
`pendingRow` показує, чи наприкінці документа лишився запис без переносу.
Він також зберігає останню порожню клітинку після коми.

Кінець у QUOTED — незакриті лапки. Звичайний символ у AFTER_QUOTE — помилка.
Порожній документ дає порожній список; один завершальний newline не створює
зайвого запису. List.copyOf захищає повернені списки від зміни.

Приклад `"Перший рядок\nДругий рядок"` займає два фізичних рядки,
але є однією CSV-клітинкою. Саме тому split/readAllLines не підходять.

## 10. WeatherCsvStorage: документ → об’єкти

read(path) отримує текст через StorageFiles, розбирає CsvParser.
Порожній документ дозволений. Перший запис має дорівнювати csvHeader;
далі кожен запис передається WeatherReadingRecord.fromFields.
До помилки додається номер логічного запису (заголовок має номер 1).
Первинна технічна cause зберігається. При помилці не повертається частковий
успішний список; імпорт цілого документа припиняється.

## 11. JsonExporter: ті самі поля, інший формат

toJson отримує ColumnMetadata, проходить записи й поля, формує пари
«екранована назва: значення». encode визначає JSON-тип:

- null → `null`;
- boolean та підтримувані числа → без лапок;
- текст, char, enum, календарний тип → рядок у лапках;
- NaN/Infinity та вкладений об’єкт → DataStorageException.

quote обходить символи: екранує лапку, зворотний слеш, newline/CR/tab,
керівні символи й UTF-16 surrogate через Unicode escape. Unicode українського
тексту зберігається. write передає JSON StorageFiles; порожній список — `[]`.
JSON-імпорт не потрібний для цієї зірочки: обов’язковий round-trip залишається CSV.

## 12. Параметри й контролер

CommandLineOptions — Java record: компілятор генерує конструктор компонентів,
accessor-методи на кшталт exportCsvPath(), equals/hashCode/toString.
Додатковий шестипараметровий конструктор делегує повному через this(...)
і зберігає старий спосіб створення параметрів.

ArgumentParser.parse обходить args. Прапорці не мають значення; після
параметра шляху потрібний наступний аргумент. Для --import-csv і --input
разом кидається помилка. --round-trip потребує --export-csv.
Парсер не читає файлів. Help/version обробляються окремо.

WeatherController.run запускає потрібний процес. ReadLegacy обробляє
старі рядки окремо й накопичує помилки, Repository містить лише коректні
вимірювання. Новий імпорт відновлює вимірювання через toReading.
PrintReading зберігає старий формат друку. Звіт/запити формують старі класи;
файловий звіт завжди стандартний, додаткові аналізи залишаються в консолі.

StorageWorkflow.validatePaths відхиляє однакові джерело й призначення,
включно з нормалізованими шляхами та наявними файловими посиланнями.
Для нового файла canonicalTarget розкриває найближчого наявного предка
через toRealPath та додає відсутні компоненти; так виявляється також
збіг призначень через посилання на батьківську папку.
Run перетворює вимірювання на плоскі записи, викликає потрібні експортери.
При --round-trip читає створений CSV й перевіряє `original.equals(restored)`.
List.equals порівнює кількість, порядок і всі записи через їх equals.
Повторені дати не видаляються: ключ date — ознака для демонстрації, не
вимога унікальності. Збіг лише кількості не вважався б достатнім доказом.

Main залишився малим: парсер → об’єкт контролера → run; його код не збільшувався.
ApplicationInfo друкує нову довідку, а версію читає з Maven-ресурсу як раніше.

## 13. ExportBenchmark: що саме вимірюється

Main benchmark створює 10 000 записів. Метод export записує 100 CSV-файлів
по 100 записів. CsvExporter(true/false) відрізняються лише кешуванням полів.
Три прогріви зменшують вплив початкового JIT; сім повторів чергують порядок.
System.nanoTime вимірює тривалість, median бере середній елемент відсортованих
семи вимірів. Files.mismatch перевіряє всі пари файлів.

Час включає форматування та I/O. Результат залежить від середовища;
це експеримент, а не обіцянка, що кеш завжди швидший. Код і результати:
[BENCHMARK.md](BENCHMARK.md).

## 14. Тести та маршрут демонстрації

Збережені попередні тести, додані окремі класи для Repository, винятку,
моделі, CSV-експорту, parser, імпорту, регресії, JSON/кешу та CLI.
JUnit перевіряє очікуваний результат через assertEquals/assertThrows;
@TempDir дає окрему тимчасову папку. Verify запускає їх і SpotBugs.
CI повторює перевірки на трьох ОС та запускає справжні JAR.

Для демонстрації:

1. Виконай команду експорту й --round-trip із README, відкрий weather.csv/json.
2. Покажи Repository<T>, анотовані поля та equals у WeatherReadingRecord.
3. Покажи ColumnMetadata.inspect і CsvExporter.toCsv: тут універсальність.
4. Покажи стани CsvParser та WeatherCsvStorage.read: тут читання назад.
5. Покажи перевірку original.equals(restored) у StorageWorkflow.
6. Для зірочки — Exporter, JsonExporter, кеш і BENCHMARK.md.
7. Відкрий зелений Actions, його JAR і створений CSV.

Не потрібно вчити код напам’ять. Важливо простежити один запис від input
до об’єкта, анотації, CSV-клітинки та відновленого об’єкта й пояснити,
де саме буде зупинено пошкоджене число, дату, лапку або файлову операцію.
