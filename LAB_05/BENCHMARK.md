# Вимірювання кешу полів

Команда з кореня після збірки:

```sh
java -cp LAB_05/target/lab05.jar ua.lpnu.kzp.lab05.ExportBenchmark
```

Виконано 18.11.2026 на Linux. Повний CSV-експорт включає формування тексту,
створення/перезапис файлів і файловий I/O. 10 000 однакових для обох режимів
записів розбиті на 100 пакетів по 100. Перед вимірюванням 3 прогріви,
потім 7 повторів зі зміною порядку режимів. Медіана зменшує вплив викидів.
Кеш розігрітий; вартість першого відкриття класу не вимірюється окремо.

```text
Java: 21.0.12.1; OS: Linux amd64
Records: 10000; batches: 100; warmup: 3; repeats: 7
Uncached median: 12.902 ms
Cached median: 11.438 ms
Uncached ns: [18521826, 13333986, 12902206, 12904056, 12087749, 11813056, 11995314]
Cached ns: [13973485, 13760226, 10444813, 10472644, 11437868, 10376669, 11502172]
Equal CSV files: 100
Includes rendering and file I/O; timing is environment-dependent, not a test assertion.

```

У цьому запуску кешований режим мав меншу медіану. Файловий кеш ОС,
JIT, GC та навантаження впливають на час; це локальний експеримент,
а не універсальна гарантія прискорення. На великому одиничному експорті
пошук полів може бути незначною частиною загального часу. Немає тесту,
який падає через повільніший кеш. Порівняно всі 100 пар файлів через
Files.mismatch; результат має бути -1 для кожної пари.

Кеш зберігає Class і Field на час життя процесу; розвантаження динамічних
classloader не є сценарієм цієї консольної програми. Дані записів не кешуються.
